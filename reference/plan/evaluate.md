아이디어 정리서 또는 작업계획서를 다기준 의사결정분석(MCDA)으로 평가해주세요.

> 이 커맨드는 직감으로 다음 단계에 진입하는 것을 막는 **정량 게이트**입니다.
> 평가 주체는 메인 에이전트가 아니라 **프로젝트 서브에이전트 패널**입니다.

## 대상 문서 결정
아래 우선순위로 대상 문서를 자동으로 결정해주세요:
1. **$ARGUMENTS에 경로가 있으면** → 해당 파일 사용
2. **현재 대화에서 아이디어 정리서/작업계획서를 방금 다루었으면** → 해당 파일 사용
3. **위 모두 해당 없으면** → `docs/proposals/idea-*.proposal.md`와 `docs/plans/plan-*.md` 중 가장 최근 수정된 파일 사용
4. 결정된 파일과 문서 유형(아이디어/작업계획서)을 알려주고 맞는지 확인 후 진행해주세요
   - 단, **앞선 커맨드(`/plan:idea`, `/plan:create`)에서 자동 연계로 실행된 경우**에는 대상이 명확하므로 확인 질문 없이 대상만 표기하고 바로 진행하세요

## 평가 기준과 가중치 (기본값 고정)
채점은 이 프로젝트의 서브에이전트(`plan`/`dev`/`ref`/`qa`/`review`)가 담당합니다.

| # | 기준 | 가중치 | 채점 에이전트 | 비고 |
|---|------|--------|--------------|------|
| 1 | 사용자·매장 가치 | 25% | plan | 문제의 크기·빈도·해결 체감 |
| 2 | 전략 정합성 | 15% | plan | 서비스 방향·기존 기능과의 시너지 |
| 3 | 구현 노력 | 20% | dev | **역산: 노력이 적을수록 높은 점수** |
| 4 | 기술 리스크 | 15% | dev + ref | 아키텍처 영향·불확실성·Tizen 의존도 |
| 5 | Tizen/플랫폼 실현성 | 10% | ref | Tizen 4.0+ / Samsung TV WebKit·리모컨·가로세로 제약 내 실현성 |
| 6 | 품질·테스트 용이성 | 10% | qa | 회귀·리소스 누수 위험, 검증 가능성 |
| 7 | 유지보수·일정 영향 | 5% | review | 기존 코드·컨벤션 부담, 마일스톤 충돌 |

- $ARGUMENTS에 가중치 조정 지시가 있으면 반영하고, 조정된 가중치를 결과에 명시해주세요 (합계 100% 검증)

## 평가 프로세스 (블라인드 패널)
1. 대상 문서를 읽어주세요
2. 채점 에이전트를 **Task tool(서브에이전트)로 병렬 호출**해주세요 (`plan`/`dev`/`ref`/`qa`/`review`)
   - 메인 에이전트가 대신 채점하지 마세요. 반드시 서브에이전트가 채점합니다
   - 각 에이전트에게는 **자신의 담당 기준만** 전달하고, 다른 에이전트의 점수는 보여주지 마세요 (블라인드)
3. 각 서브에이전트에게 다음을 전달해주세요:
   - 대상 문서 경로 (직접 읽고 필요 시 코드베이스 확인)
   - 담당 기준의 정의와 채점 지침
   - 반환 형식: 기준별 `점수(1~5 정수) + 근거 2~3줄 + 점수를 올리기 위한 보완 제안 1개`
4. 점수를 집계해주세요:
   - 2명이 채점한 기준(기술 리스크: dev + ref)은 **평균** 사용
   - 두 점수 차이가 **2점 이상이면 "쟁점"**으로 표기 (편차 자체가 리스크 신호)
   - 종합 점수 = Σ(기준 점수 × 가중치)

## 판정 밴드
- **🟢 진행 권장**: 종합 ≥ 4.0
- **🟡 보완 후 진행**: 3.0 ≤ 종합 < 4.0 — 자동 보완 루프 진입
- **🔴 보류·재검토**: 종합 < 3.0 — 자동 보완 루프 진입 (단, 루프로 해결되지 않으면 구조적 재검토)

## 자동 보완 루프 (🟢 미달 시)
종합 점수가 4.0 미만이면 **사용자에게 묻지 말고 자동으로 보완 → 재평가를 반복**해주세요:

1. **보완 반영**: 패널의 "보완 제안"을 대상 문서에 직접 반영해주세요
   - 반영 부분에 `<!-- plan:evaluate 보완(N차) -->` 마커 표시
   - ⚠️ **의사결정성 보완은 자동 반영 금지**: 범위 축소, 기능 제거, 방향 전환 등 사용자 의도를 바꾸는 보완은 반영하지 말고 보류 목록에 모아두세요
2. **재평가**: 블라인드 패널을 다시 호출해 N차 평가를 실행해주세요 (이력 보존)
3. **루프 종료 조건** (하나라도 충족 시 종료):
   - ✅ 종합 ≥ 4.0 도달 → "후속 처리"로 진행
   - 🛑 **최대 3차 평가 도달** → 중단 후 보고
   - 🛑 **수렴 정체**: 직전 차수 대비 상승 폭 < 0.2 또는 하락 → 중단 (보완으로 해결되지 않는 구조적 한계 신호)
   - 🛑 **남은 보완이 전부 의사결정성** → 중단 후 보류 목록을 사용자에게 보고
4. 각 차수마다 진행 상황을 간단히 보고해주세요: `2차 평가: 3.2 → 3.6 (+0.4) — 루프 계속`

## 결과 기록
대상 문서 끝에 아래 형식으로 추가해주세요. 이미 평가 섹션이 있으면 **기존 점수를 이력 줄로 남기고** 새 평가로 갱신해주세요:

```markdown
## 다기준 평가 (MCDA)
<!-- plan:evaluate 추가 -->
평가일: YYYY-MM-DD | 평가 차수: N차 (이전: 3.2점)

| 기준 | 가중치 | 점수 | 가중점수 | 채점 |
|------|--------|------|----------|------|
| 사용자·매장 가치 | 25% | 4.0 | 1.00 | plan 4 |
| 기술 리스크 | 15% | 3.5 | 0.53 | dev 3 / ref 4 |
| ... | | | | |

**종합: 3.85 / 5.0 → 🟡 보완 후 진행**

### 쟁점 (에이전트 간 편차 ≥ 2)
- 기술 리스크: dev 2 vs ref 4 — {편차 사유 요약}

### 에이전트별 근거 요약
- **plan**: {근거 요약}
- **dev**: {근거 요약}
- ...

### 보완 제안 (점수를 올리려면)
1. {보완 제안}
2. {보완 제안}
```

## 평가 완료 출력
```
📊 다기준 평가 완료
📄 파일: {문서 경로} ({아이디어 정리서 | 작업계획서})
🤖 채점: 서브에이전트 5명 (plan/dev/ref/qa/review, 블라인드 패널)
🔁 평가 차수: 3차 (추이: 3.2 → 3.6 → 4.1)

종합: 4.1 / 5.0 → 🟢 진행 권장
최고: 전략 정합성 (5) | 최저: 품질·테스트 용이성 (3)
쟁점: 1건 (기술 리스크) | 보류된 의사결정성 보완: 1건
```

## 후속 처리
자동 보완 루프까지 끝난 뒤, 최종 결과에 따라 처리해주세요:

### 🟢 도달 (최초 또는 루프 후) — 자동 진행
**사용자에게 묻지 말고 `▶ 자동 진행: {커맨드}` 한 줄 보고 후 즉시 다음 단계를 이어서 실행**하세요:
- 아이디어 정리서 → `/plan:create {경로}` 절차 실행
- 작업계획서 → `/plan:review {경로}` 절차 실행
- 보류된 의사결정성 보완이 있으면 보고와 함께 다음 단계에 전달하세요 (계획서 `리스크 & 고려사항`에 반영)

### 루프 중단 후에도 🟢 미달 — 선택형 (진짜 의사결정)
**AskUserQuestion 도구로 선택지를 제시**하고, 사용자가 선택하면 즉시 실행하세요:
- **🟡 수준 (3.0~3.9)**:
  - **현재 점수로 진행** → 위 🟢와 동일한 다음 단계 실행 (중단 사유를 명시한 채)
  - **보류된 의사결정성 보완 검토** → 보류 목록을 하나씩 AskUserQuestion으로 결정받아 반영 후 재평가 1회
  - **여기서 종료**
- **🔴 수준 (< 3.0)**:
  - **아이디어 재구체화** → `/plan:idea {경로}` 절차로 회귀 (점수 추이·중단 사유를 입력으로 전달)
  - **여기서 종료**
