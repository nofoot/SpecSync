작업계획서를 작성하기 **전 단계**입니다. 곧바로 계획을 세우지 말고, 먼저 아이디어를 폭넓게 도출(발산)한 뒤 추려내고(수렴), 아이디어 정리서로 마무리해주세요.

$ARGUMENTS 내용이 있으면 아이디어 도출의 출발점으로 활용합니다. 없으면 무엇에 대한 아이디어를 찾는지 먼저 물어봐주세요.

## 목적
- 정답을 찾는 게 아니라 **선택지를 넓히는** 단계입니다.
- 결과물은 `docs/proposals/`의 아이디어 정리서이며, 이후 `/plan:evaluate`(게이트) → `/plan:create`로 이어집니다.
- 따라서 결론을 서두르지 말고, 다양한 접근과 트레이드오프를 충분히 펼쳐주세요.

## 1단계: 문제 정의 (가볍게)
아이디어를 내기 전에 무엇을 풀려는지 한두 가지만 짧게 확인해주세요. (요구사항 전수조사는 `/plan:create`의 몫이므로 여기서는 깊게 캐묻지 마세요.)
- **무엇을** 개선/구현하고 싶은가?
- **왜** 지금 이게 중요한가? (성공 기준이 무엇인가?)

## 2단계: 아이디어 발산
한 번에 여러 관점에서 아이디어를 제시해주세요. 가능하면 3~5개의 서로 **다른 방향**을 제안합니다.

각 아이디어는 다음 형식으로 간결하게:
- **아이디어명**: 한 줄 핵심
- **접근 방식**: 어떻게 동작/구현되는가
- **장점**: 무엇이 좋은가
- **단점/리스크**: 무엇이 걸리는가
- **난이도/비용**: 대략적인 구현 부담 (상/중/하)

### 발산 규칙
- 처음부터 "현실적인 것"만 고르지 마세요. 보수적인 안 + 과감한 안 + 절충안을 섞어주세요.
- 코드베이스를 확인해 **기존 구조를 재사용하는 안**과 **새로 만드는 안**을 함께 제시하면 좋습니다.
  예: "기존 `SignageManagerRenderer`를 확장하는 방식 vs 별도 모듈로 분리하는 방식"
- Tizen/Samsung TV 호환성 제약이 관련되면 아이디어별로 짚어주세요.
- 답이 막히는 항목은 **제가 2~3개의 가능성을 제안**하고 사용자가 고르게 해주세요 (AskUserQuestion 활용).
- 사용자가 "더 없나?", "다른 방향은?" 이라고 하면 새로운 축으로 추가 발산해주세요.

## 3단계: 수렴 (비교·추천)
발산이 충분해지면 아이디어들을 비교해 정리해주세요.
- **비교표**: 아이디어 × (효과 / 비용 / 리스크 / 호환성) 요약
- **추천**: 가장 유력한 1~2개와 그 이유
- **버리는 안**: 왜 제외하는지 한 줄

사용자와 대화하며 후보를 좁혀가세요. 한 번에 결론 내지 말고 사용자의 선호를 반영해주세요.

## 4단계: 아이디어 정리서 생성
방향이 좁혀지면 아래 구조로 정리서를 생성해주세요. (여기서 **작업계획서는 만들지 않습니다** — 기술 설계·일정 산정은 `/plan:create`의 몫입니다.)

### 정리서 구조
```
# 아이디어: {제목}

## 문제 정의
- 누가, 언제, 어떤 불편을 겪는가
- 현재의 대응 방식 (AS-IS)

## 제안 (TO-BE)
- 핵심 아이디어 한 줄 요약
- 사용자 관점 동작 흐름 (러프 시나리오)

## 기대 효과
- 정성적/정량적 기대 효과

## 검토한 대안
- 발산 단계에서 검토했으나 채택하지 않은 안과 그 이유

## MVP 범위 가설
- 최소 범위 (이것만 되면 검증 가능)
- 이후 확장 후보

## 미해결 질문
- /plan:create 단계에서 확정해야 할 항목
```

### 생성 절차
1. 정리서를 프로젝트 루트의 `docs/proposals/` 디렉토리에 저장해주세요
   - 파일명: `idea-YYYYMMDD-간단설명.proposal.md`
   - 예시: `idea-20260616-템플릿-즐겨찾기.proposal.md`
2. 생성 완료 후 요약을 알려주세요:
   ```
   💡 아이디어 정리서 생성 완료
   📄 파일: docs/proposals/idea-20260616-템플릿-즐겨찾기.proposal.md
   📌 제목: 템플릿 즐겨찾기
   ❓ 미해결 질문: 3건
   ```

## 후속: 다기준 평가 자동 실행
정리서 생성 완료를 보고한 뒤, **사용자에게 묻지 말고 즉시 `/plan:evaluate {정리서 경로}` 절차를 이어서 실행**해주세요.
- 아이디어 정리서는 평가(주 게이트)를 거쳐야 다음 단계 진입 여부가 결정됩니다.
- 평가 이후의 분기는 `/plan:evaluate`의 "후속 처리"를 따릅니다.
- 예외: 사용자가 평가 생략을 명시적으로 요청한 경우에만 건너뛰고, AskUserQuestion으로 다음을 제시하세요:
  - **작업계획서 작성** → `/plan:create {정리서 경로}` 절차 실행
  - **여기서 종료**
