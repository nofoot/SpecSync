작업계획서를 프로젝트에 정의된 에이전트들이 검토하도록 해주세요.

## 대상 작업계획서 결정
아래 우선순위로 대상 작업계획서를 자동으로 결정해주세요:
1. **$ARGUMENTS에 경로가 있으면** → 해당 파일 사용
2. **현재 대화에서 작업계획서를 방금 생성했거나 언급했으면** → 해당 파일 사용
3. **위 모두 해당 없으면** → `docs/plans/` 에서 가장 최근 수정된 파일 사용
4. 결정된 파일을 알려주고 맞는지 확인 후 진행해주세요

## 에이전트 로딩
1. `.claude/agents/` 디렉토리에서 모든 `.md` 파일을 읽어주세요
   - 각 `.md` 파일 하나가 Claude Code 네이티브 서브에이전트 정의입니다
   - 파일명(확장자 제외)이 에이전트 식별자입니다 (예: `plan.md` → `plan`, `qa.md` → `qa`)
2. 디렉토리가 없거나 파일이 없으면 사용자에게 알려주세요:
   ```
   ⚠️ 에이전트 정의를 찾을 수 없습니다.
   .claude/agents/ 디렉토리에 에이전트 .md 파일을 생성해주세요.
   ```
3. 로딩된 에이전트 목록을 먼저 보여주세요 (현재 프로젝트 기준 예시):
   ```
   👥 로딩된 에이전트: 6명
   1. plan   — 요구사항/영향도 분석, 구현 전략
   2. dev    — 구현 관점 실현 가능성
   3. review — 컨벤션·코드 품질·에러 처리
   4. qa     — 회귀·리소스 누수·에러 시나리오
   5. ref    — Tizen/Samsung TV 호환성
   6. doc    — 문서 영향·갱신 필요성
   ```

## 에이전트 파일 형식
각 `.md` 파일은 YAML 프론트마터 기반의 **네이티브 서브에이전트 정의**입니다:
- `name:` — 에이전트 식별자 (Task tool 호출 시 `subagent_type`으로 사용)
- `description:` — 역할 설명 (이 관점으로 검토)
- `model:` — 해당 에이전트가 사용하는 모델

## 검토 프로세스
1. 대상 작업계획서를 읽어주세요
2. 각 에이전트를 **반드시 Task tool(서브에이전트 호출)로 실행**해주세요
   - `subagent_type`에 에이전트 `name`(파일명)을 지정하세요
   - 메인 에이전트가 역할극으로 검토를 흉내 내지 마세요. 서브에이전트로 호출해야 에이전트별 모델·도구 제한이 실제로 적용됩니다
   - 서로 독립적인 에이전트는 병렬로 호출하세요
3. 각 서브에이전트에게 다음을 전달해주세요:
   - 작업계획서 파일 경로
   - 자신의 역할 관점에서 실제 코드베이스를 분석하여 검토할 것 (보완점·리스크·누락 사항)
   - 검토 결과를 텍스트로 반환할 것
4. 반환된 검토 결과를 메인 에이전트가 작업계획서에 반영해주세요
   - 추가한 내용은 `<!-- {에이전트 파일명} 추가 -->` 주석으로 표시 (예: `<!-- qa.md 추가 -->`)
   - 기존 작업계획서 내용은 유지하면서 보완/추가만 합니다

## 검토 완료 출력
모든 에이전트 검토가 끝나면 다음 형식으로 요약해주세요:

```
🔍 에이전트 검토 완료
📄 파일: {작업계획서 경로}
👥 검토 에이전트: {N}명

[{에이전트1 이름} — {파일명}]
- {주요 검토 결과 요약}

[{에이전트2 이름} — {파일명}]
- {주요 검토 결과 요약}

...
```

## 다음 작업 제안 (선택형)
검토 보고 후, 후속 작업을 텍스트로 안내하지 말고 **AskUserQuestion 도구로 선택지를 제시**해주세요.
사용자가 선택하면 해당 작업을 즉시 실행하세요:
- **TODO 리스트 생성 (권장)** → `/plan:todo {작업계획서 경로}` 절차 실행
- **여기서 종료** → 추가 작업 없이 종료

단, 검토에서 **차단급 이슈**(계획의 전제를 뒤집는 결함, 아키텍처 충돌, 범위 재정의 필요)가 발견되면 TODO 진행을 권하지 말고 해당 이슈를 먼저 보고하세요.
