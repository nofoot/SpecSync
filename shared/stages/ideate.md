# ideate: 아이디어 발산과 수렴

Spec을 만들기 전에 방향을 정한다. 목적은 정답이 아니라 선택지를 넓힌 뒤 좁히는 것이다. 요구사항을 자세히 캐묻는 것은 `clarify.md`의 몫이므로 여기서는 하지 않는다.

## 1. 문제 확인

무엇을 풀려는지, 왜 지금 중요한지(성공 기준)만 짧게 확인한다. 입력에 이미 있으면 건너뛴다.

## 2. 발산

관련 코드를 확인한 뒤 서로 **다른 방향**의 안을 3~5개 제시한다.

- 보수적인 안, 과감한 안, 절충안을 섞는다.
- 기존 구조를 재사용하는 안과 새로 만드는 안을 함께 둔다.
- principles의 제약(플랫폼, 호환성 등)이 관련되면 안마다 짚는다.

각 안의 형식:
- **이름**: 한 줄 핵심
- **접근 방식**
- **장점 / 단점·리스크**
- **구현 부담**: 상 / 중 / 하

사용자가 "다른 방향은?"이라고 하면 새 축으로 추가 발산한다.

## 3. 수렴

- 비교표: 안 × (효과 / 비용 / 리스크 / 제약 적합성)
- 추천 1~2개와 이유
- 제외하는 안과 이유 한 줄

AskUserQuestion으로 방향을 고르게 한다. 한 번에 결론을 강요하지 않는다.

## 4. 이어서

방향이 정해지면 `create.md`를 수행한다. 이때:
- 선택한 안을 요구사항의 기반으로 쓴다.
- 채택하지 않은 안과 이유를 `spec.md`의 `## 검토한 대안`에 기록한다.
- 발산 중 나온 결정되지 않은 사항은 `## 미해결 질문`으로 옮긴다.
- 선택한 안이 독립 배포 가능한 기능 여러 개로 나뉘면 epic으로 판별한다.
